文献处理软件 26.10.19.04

启动
1. 完整解压源码，保留十四个 Python 模块及 update_helper.ps1、requirements.txt 与图标。
2. Windows 双击 start_paddleocr_pdf_to_md_SAFE.bat。
3. 首次使用需要 Python 3.9+ 和网络；Linux/macOS 使用带 Tkinter 的 Python 运行主入口。

入口1：PDF OCR 转 MD功能
选择输入/输出文件夹，配置 PaddleOCR Token 后开始。
可选启用 LLM 质量核验；超过 50MB 的 PDF 会自动拆分再合并。
勾选“自动检测外文并翻译”时，使用入口2设置处理新完成的 OCR 输出。
勾选后可直接在 OCR 页的“自动翻译核对设置（两入口共用）”启用二次核对或文本校对，在“发现问题时”选择“大模型裁决”，并配置裁决模型。
仅填写裁决模型不会启用检查或切换模式；开始前设置，运行中修改对下次任务生效。

入口2：外文文献翻译功能
扫描已有 MD，使用前 300 字符判断语言；已是目标语言则跳过。
可设置来源/目标语言，分别为翻译、二次核对、文本校对和裁决选择模型。
偏好设置 → 翻译模型 → 翻译分段预算：按模型输入上限的 50%–80% 分段，默认 50%。
拉取模型时读取接口提供的限制；无数据时用 DeepSeek-V4.1-Flash 的 1,000,000 上下文 / 256,000 输出兜底，各模型可手动修改输入上限。
切换接口或模型会重置手动覆盖，接口限制缓存仅用于相同接口与模型。
预算包含提示词、消息和核对所需译文，并预留输出。token 使用 UTF-8 字节数加消息开销保守估算，优先保留完整段落；译文膨胀或输出截断时缩小原文重做。
支持 DeepSeek、Kimi/Moonshot、Doubao/火山方舟等 OpenAI compatible 服务。
译文可输出到原文件夹或指定目录，文件名可加 TRANSLATED_ 前缀或 _TRANSLATED 后缀。
保留原文，已有译文不会覆盖；每份新译文另存 translation.json 检查报告。
选择大模型裁决后，翻译分歧和校对疑点都会交给指定模型复核；仅校对任务同样支持。明确批准且无遗留问题才通过。
日志记录实际检查设置、裁决模型、结果及理由；报告保留原校对疑点、独立裁决和 pendingReasons。真正仍有问题或裁决不明确时继续待处理，不自动上传。
勾选同目录保存时，译文位置灰色锁定并跟随原文位置。选择新目录须先确认覆盖；取消任一步均保留原设置。

Markdown 整理（工具栏“MD 整理”）
可选单个 MD 或文件夹，包含子目录；原文和译文都能整理，批量扫描跳过已有整理稿。
分别配置整理模型与核验模型；每次尝试只排版一次，再独立校对，不生成第二份整理稿，不翻译或润色原文。
按共用 50%–80% 预算比例分段，完整代码块、公式和表格不拆开；超限时提示换模型或调整上限。
保留原文，输出可同目录或指定目录；文件名可选 FORMATTED_ 前缀或 _FORMATTED 后缀，另存 .formatting.json 报告。
核验失败、内容变化或疑点会标记待处理并弹窗；不自动再整理，不自动上传。
关闭整理窗口不会中止任务，可重新打开查看／停止；整理中阻止 OCR／翻译和安装更新。

统一 LLM 服务（偏好设置 → LLM 服务）
可启用所有 LLM 共用服务商、Base URL 与 API Key，覆盖 OCR 的 LLM 核验、翻译、核对、校对、裁决、整理与核验；各任务仍单独选择模型。
PaddleOCR 的服务／模型／Token 与 GitHub 上传 Token 独立。
启用后其余任务的连接控件置灰；点击修改时提示“您已选择“所有服务共用一个LLM服务商”，是否需要强制覆盖设置？”
确认后关闭共用并解锁单独编辑；取消则保持锁定。关闭共用保留当前值，更换服务后请重新拉取并选择模型。
关闭的下拉框不再因滚轮误改值；滚轮滚动页面，主动展开下拉框后选择。

处理问题弹窗
显示具体问题、原文、第一稿、第二稿（如有）及完整报告。
可选“保留第一稿／删除并重试上一步／保留第二稿”，第二稿不存在时不显示。
尚无稿件的 API 失败只提供跳过或重试。保留疑点稿继续待处理；重试只丢弃本次生成稿并重做当前分段／文件，不删除原文。
模型裁决模式仍先调用模型；明确通过时不弹人工选择，未解决问题才显示上述选项。

GitHub 上传
打开“偏好设置 → GitHub 上传 → 打开上传设置向导”。
1. 连接 GitHub：按按钮创建并粘贴 Token，选择目标仓库并允许 Contents 读写。
2. 选择仓库：从读取的列表选择，或粘贴 GitHub 仓库链接；新建仓库时勾选 Add a README file。
3. 选择保存位置：自动使用真实默认分支，文件夹留空表示根目录，也可浏览已有目录或填写新目录。
4. 确认摘要并保存，按需启用自动上传。取消会保留原设置；修改凭据或目的地后需要重新检查。
向导只读检查，不会写入测试文件、创建仓库或分支；实际写入权限和分支保护在上传时校验。
上传内容可选“仅上传原文／仅上传翻译稿／同时上传”，同时适用于自动上传和手动补传；原文指来源或 OCR Markdown，不含 PDF。
点击“手动扫描与补传”，选择本地文件夹和内容，扫描后默认选中远端缺少且核验通过的文档，可调整选择后确认上传。
远端已有路径跳过，上传前重新检查报告和指纹，不覆盖远端同名文件。旧 OCR 核验报告缺少指纹时，请重新进行手动 LLM 核验。
Token 仅保留本次运行；模型 Key 与 PaddleOCR Token 按原方式明文保存在本机配置，请勿共享。
上传会创建提交，不会自动创建 PR。

小窗口
侧栏宽度按文字与字体尺寸适配，中英文切换后重新计算；窄窗口或低高度窗口使用顶部导航。
扫描、修复 JSON、手动检验等工具按钮直接显示并自动换行，卡片和控件统一底色。
开始/停止与日志固定可见；服务和模型配置收纳在独立的“偏好设置”窗口。
拖动分隔条可调整日志区高度。标签按文字自然宽度排版，空间不足时移到输入框上方；说明与模型摘要自动换行。

汉英界面切换
在“偏好设置 → 界面语言”中选择 English / 中文，即时生效并记忆到下次启动。
也可点击主界面右上角“文/A”图标直接切换。界面语言不改变文献的来源/目标语言、模型或文件路径。

复制功能
日志有“复制日志”，更新页有“复制更新信息”；文本／状态／路径可右键复制，文本框支持 Ctrl+A／Ctrl+C。
报错、警告、信息弹窗文字可选择并有“复制信息”；稿件／核对报告有“复制全文”。

本地 ZIP 更新
偏好设置 → 软件更新 → 选择更新 ZIP → 确认版本／类型／来源 → 安装并重启。
支持直接导入本仓库的 GitHub 源码 ZIP；不需要重新打包。
也可选择“正式发行版（Release）／最新代码（main）”→“检查 GitHub 更新”→查看说明→“下载此版本”→校验后“安装并重启”。
联网更新固定来自 CHNAQW/paddleocr_usage，仅主动点击时联网，不自动检查、安装或下载依赖。正式发行版优先完整更新 ZIP，否则下载对应源码；main 固定到检查时的提交。
下载失败、取消、指纹或版本不符时清理临时文件，当前程序保持运行。
源码直接从 codeload.github.com 下载固定提交；main 检查遇 API 403／429 时尝试官方 Atom 与原始源码入口。代理也可能导致 403，请检查其 GitHub 路由规则。
助手使用编码命令启动，启动前创建 install.log，并捕获 helper-output-<id>.log；失败详情可复制，重试保留旧日志。
若旧 EXE 自己的助手无法启动，须先重新打包并手动替换成 26.10.19.04，之后再测试软件内更新。
首次须手动换成带固定启动器的新 EXE；以后用内置 Python 运行时加载用户目录中的更新源码。
源码 APP_VERSION 须更高，依赖须匹配内置运行时。新增未打包依赖或更换启动器时需完整程序更新包。
完整程序 ZIP 由打包脚本自动生成，含新版 EXE、update.json 和 SHA-256；也可用 make_update_package.py 生成。
安装前须结束 OCR／翻译／检查任务，保存设置后退出。新版启动失败时尝试恢复旧版，并保留日志。
源码安装于 %LOCALAPPDATA%\PaddleOCR\updates。界面显示源码版本，启动器文件名／属性不因此改变；单独复制 EXE 不会携带用户目录里的源码更新。
只导入可信来源；文件哈希校验不是数字签名。源码运行可校验，自动安装限 Windows EXE。

构建 Windows EXE
双击 build_paddleocr_pdf_to_md_EXE.bat，需 Python 3.9–3.13。
输出：PaddleOCR_PDF_to_MD_EXE\PaddleOCR_PDF_to_MD_26.10.19.04.exe
校验：同目录下的 .exe.sha256.txt。
固定运行缓存：%LOCALAPPDATA%\PaddleOCR\PDFToMarkdown\26.10.19.04
界面与文件名版本：26.10.19.04；Windows 数字文件/产品版本：26.10.19.4。
版本更新不代表 EXE 已编译发布；不要关闭安全防护或添加排除项。
