文献处理软件 26.10.18.03

启动
1. 完整解压源码，保留九个 Python 模块、requirements.txt 与图标。
2. Windows 双击 start_paddleocr_pdf_to_md_SAFE.bat。
3. 首次使用需要 Python 3.9+ 和网络；Linux/macOS 使用带 Tkinter 的 Python 运行主入口。

入口1：PDF OCR 转 MD功能
选择输入/输出文件夹，配置 PaddleOCR Token 后开始。
可选启用 LLM 质量核验；超过 50MB 的 PDF 会自动拆分再合并。
勾选“自动检测外文并翻译”时，使用入口2设置处理新完成的 OCR 输出。

入口2：外文文献翻译功能
扫描已有 MD，使用前 300 字符判断语言；已是目标语言则跳过。
可设置来源/目标语言，分别为翻译、二次核对、文本校对和裁决选择模型。
偏好设置 → 翻译模型 → 翻译分段预算：按模型输入上限的 50%–80% 分段，默认 50%。
拉取模型时读取接口提供的限制；无数据时用 DeepSeek-V4.1-Flash 的 1,000,000 上下文 / 256,000 输出兜底，各模型可手动修改输入上限。
切换接口或模型会重置手动覆盖，接口限制缓存仅用于相同接口与模型。
预算包含提示词、消息和核对所需译文，并预留输出。token 使用 UTF-8 字节数加消息开销保守估算，优先保留完整段落；译文膨胀或输出截断时缩小原文重做。
支持 DeepSeek、Kimi/Moonshot、Doubao/火山方舟等 OpenAI compatible 服务。
译文可输出到原文件夹或指定目录，文件名可加 TRANSLATED_ 前缀或 _TRANSLATED 后缀。
保留原文，已有译文不会覆盖；每份新译文另存 translation.json 检查报告。
勾选同目录保存时，译文位置灰色锁定并跟随原文位置。选择新目录须先确认覆盖；取消任一步均保留原设置。

GitHub 上传
打开“偏好设置 → GitHub 上传 → 打开上传设置向导”。
1. 连接 GitHub：按按钮创建并粘贴 Token，选择目标仓库并允许 Contents 读写。
2. 选择仓库：从读取的列表选择，或粘贴 GitHub 仓库链接；新建仓库时勾选 Add a README file。
3. 选择保存位置：自动使用真实默认分支，文件夹留空表示根目录，也可浏览已有目录或填写新目录。
4. 确认摘要并保存，按需启用自动上传。取消会保留原设置；修改凭据或目的地后需要重新检查。
向导只读检查，不会写入测试文件、创建仓库或分支；实际写入权限和分支保护在上传时校验。
上传选项由两个入口共用，只上传本次核验通过的 Markdown，不覆盖远端同名文件。
Token 仅保留本次运行；模型 Key 与 PaddleOCR Token 按原方式明文保存在本机配置，请勿共享。
上传会创建提交，不会自动创建 PR。

小窗口
宽窗口使用侧栏和并排选项，窄窗口使用顶部导航。
扫描、修复 JSON、手动检验等工具按钮直接显示并自动换行，卡片和控件统一底色。
开始/停止与日志固定可见；服务和模型配置收纳在独立的“偏好设置”窗口。
拖动分隔条可调整日志区高度。标签按文字自然宽度排版，空间不足时移到输入框上方；说明与模型摘要自动换行。

汉英界面切换
在“偏好设置 → 界面语言”中选择 English / 中文，即时生效并记忆到下次启动。
也可点击主界面右上角“文/A”图标直接切换。界面语言不改变文献的来源/目标语言、模型或文件路径。

构建 Windows EXE
双击 build_paddleocr_pdf_to_md_EXE.bat，需 Python 3.9–3.13。
输出：PaddleOCR_PDF_to_MD_EXE\PaddleOCR_PDF_to_MD_26.10.18.03.exe
校验：同目录下的 .exe.sha256.txt。
固定运行缓存：%LOCALAPPDATA%\PaddleOCR\PDFToMarkdown\26.10.18.03
界面与文件名版本：26.10.18.03；Windows 数字文件/产品版本：26.10.18.3。
版本更新不代表 EXE 已编译发布；不要关闭安全防护或添加排除项。
